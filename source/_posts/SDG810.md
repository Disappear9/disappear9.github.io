逛闲鱼时发现有人标价240块卖不包好坏的SDG810函数发生器  
众所周知，咸鱼的 `不包好坏==就是坏的` 和卖家聊一聊，貌似是从学校收的，一台能开机无输出，一台不启动，开机卡在鼎阳Logo，讲价一下200块一台包邮拿下两台  

## 开箱

设备的保存情况还可以，灰不多，一台外壳还是原来的灰白色，一台估计是放在教室窗户边上的位置，外壳被晒的有点发黄  
先开看能正常启动没输出的这台  
插电开机，检查版本号：

从[鼎阳中国官网](https://www.siglent.com/support/resource/?current=siglent-firmware&productCategory=21&product=713)查找固件更新，可以发现这是2016年的固件，和从序列号查询到的生产日期基本一致  

![](/pictures/SDG810/version-log.webp)  

使用示波器测量输出，左侧的 `Sync Out/Ext Trig` 接口在打开同步功能时有3 Vpp左右的窄脉冲，脉冲频率跟随面板上设定的频率  
右侧的 `Output channel1` 无论怎样调节参数，只会输出一个固定的-3.8 V 直流  

## 拆解
Google上搜了一下找到了[SDG800 Series Function Generator Service Manual](https://siglentna.com/wp-content/uploads/dlm_uploads/2022/02/SDG800-Service-Manual.pdf) 服务手册  
非常常见的滑盖结构，卸下提手后拆掉一颗固定外壳的螺丝和两颗固定后框的螺丝即可滑动拆除外壳  
拆掉所有排线和插头后，卸下四颗螺丝，向后推即可取下主板  
![](/pictures/SDG810/disasm-mb.webp)  


## 检查主板
![](/pictures/SDG810/inspect-mb.jpg)  
鼎阳的设备并没有像国外大厂一样提供仪器的图纸，甚至连框图都没有，所以我们只能自己分析了  
`EP4CE10F17C8N` FPGA 发送数据控制 `DAC904E` DAC  
DAC输出的互补电流信号到 `OPA695` 差分转单端，然后经过几组LC网络合成波形  
FPGA发出的另一组信号控制 `DAC8580` 生成直流电压，输出到 `74HC4051D` 多路复用器  
FPGA控制多路复用器的地址线，多路复用器输出到运放 `AD8512`  
运放作为电压跟随器，将直流电压输入到 `DAC904E` 的REF_IN引脚，控制DAC输出波形的幅度  

![](/pictures/SDG810/inspect-mb2.webp)  
之后的信号路径就简单多了，合成的波形经过几个信号继电器和可切换的衰减器到运放 `LMH6702MA`  
低电平的信号由这颗运放的输出经过两个24.9Ω电阻直接引出  
更高电平的信号则需要再经过运放 `THS3095` 放大后输出  

## 维修第一台（无输出）
### 测量
手册38页列出了电压测试点的位置    
![](/pictures/SDG810/fix1.webp)  
万用表测了一遍发现所有电压都正常  
![](/pictures/SDG810/fix2.webp)  
手册41页写到测试点TP1是 `AC waveform` ，通过刚才的分析我们已经得知TP1是运放OPA695的输出  
使用示波器可以测得我们设定输出的正常的波形，这说明FPGA到OPA695没有问题的  

测量运放LMH6702的第6脚输出，发现运放只输出了一个恒定的-0.4V  
仔细查看LMH6702，发现周围电阻有烧焦的痕迹，估计是学生乱接线电流倒灌导致的  
![](/pictures/SDG810/fix3.webp)  
这也就是为什么仪器的前面板上写着 `Not reverse input protected`  
上面还有一个双二极管D3，提供±5V的反向电压保护  
（保了，但是只能保一点点）  

### 维修
不是太贵的运放就尽量别在淘宝买了，容易一买一个不吱声  
LMH6702MA立创没货，我点了下立刻订货，顺便买了一些0805封装的24.9Ω电阻和BAV99双二极管  
然后没过两小时立创给我打了个电话说订不到  
绝了你订不到给我个订货按钮干嘛啊  
参考eevblog论坛上的帖子[Help fixing Siglent SDG805](https://www.eevblog.com/forum/repair/help-fixing-siglent-sdg805/)，他的设备里U15用的是 `OPA695` ，查看一下数据手册，引脚定义基本一样，唯一的区别是OPA695的8脚是禁用，而LMH6702的8脚是NC  
对PCB进行一个一眼盯针，8脚应该是悬空的，OPA695的手册里说 `保持开路或保持高电平可使器件正常运行` ，那么我直接用OPA695替换上去应该是没问题的  

更换U15，两个24.9Ω电阻和一个BAV99双二极管后，输出正常了  
![](/pictures/SDG810/fix4.webp)  

## 维修第二台（不启动）
### 尝试U盘恢复
搜索后发现应该是固件损坏了，可以下载恢复文件来制作一个恢复U盘  
[Instrument Stuck at Boot Screen - Recovery](https://siglent.tawk.help/article/instrument-stuck-at-boot-screen-recovery)  
翻出来一个8G的U盘，按照教程制作恢复U盘，插到仪器上开机，什么都没有发生  
仔细看了下附带的instruction，里面写道 `data recovery function require the version 1.08.01.13R5` ，上一台的固件是12R2，估计这台也差不多，那U盘恢复这条路就寄了

对比之前给SDS800用的脚本，估计是早期鼎阳写的bug，原本是取 `MD5_PR` 和 `MD5_SRLN` 的返回值，结果把命令也塞进去了  
使用下面的Python脚本计算授权码  
{% codeblock lang:python %}
#!/usr/bin/env python3
import hashlib

SERIAL = "SDGXXXXXXXXXXX" # 替换成你的序列号

SEED = (b"5zao9lyua01pp7hjzm3orcq90mds63z6zi5kv7vmv3ih981vlwn06txnjdtas3u2wa8msx"
        b"61i12ueh14t7kqwsfskg032nhyuy1d9vv2wm925rd18kih9xhkyilobbgy")

PRODUCT = b"MD5_PR SDG800\n"
BAND_STR = {5: b"5M", 10: b"10M", 30: b"30M"}
MODEL = {5: "SDG805", 10: "SDG810", 30: "SDG830"}
FIXUP = {ord("0"): "2", ord("1"): "3", ord("l"): "m", ord("o"): "p"}


def pad(data, size):
    return data[:size].ljust(size, b"\x00")

def map_byte(b):
    if 48 <= b <= 57 or 97 <= b <= 122:
        c = b
    else:
        r = b % 36
        c = 48 + r if r <= 9 else 97 + r - 10
    return FIXUP.get(c, chr(c))

def license_code(serial, band):
    srl = b"MD5_SRLN " + serial.encode() + b"\n"
    blob = (SEED
            + pad(PRODUCT, 32)
            + pad(BAND_STR[band], 5)
            + pad(srl, 32)
            + pad(srl, 32)
            + b"\x00" * 16)
    return "".join(map_byte(b) for b in hashlib.md5(blob).digest()).upper()

def main():
    print("序列号  %s" % SERIAL)
    for band in (5, 10, 30):
        print("%-7s %2d MHz  %s" % (MODEL[band], band, license_code(SERIAL, band)))

if __name__ == "__main__":
    main()
{% endcodeblock %}

## 校准
如果很不幸你在没有闪存的备份的情况下擦除了闪存，那就只能手动校准了（比如我的其中一台设备，操作时不小心在插着SD卡的情况下开机了）  
首先升级固件到 `1.08.01.13R9` 版本，高于这个版本菜单中就没有自校准功能了 [Firmware and Software Downloads - siglenteu](https://www.siglenteu.com/service-and-support/firmware-software/waveform-generators/#sdg800-series)  
校准用的Python脚本可以在这里下载到 [Re: Siglent SDG6000X Calibration](https://www.eevblog.com/forum/testgear/siglent-sdg6000x-calibration/msg5272110/#msg5272110)  
或者查找网页存档 [SIGLENT TECHNOLOGIES--Rigorous, Concentration, Innovation！](https://www.siglent.com/ENs/gjjrj.aspx?id=209)  

根据Instructions，SDG800系列只有两个项目需要校准， `Feedback Channel Adjust` （0V, 1V, -1V的反馈通道校准） 和 `Frequency Response Calibration` （频响校准）  
流程是 `反馈通道校准 -> 自校准 -> 频响校准`  
**你最起码需要有一台6位半的万用表**，U2004A功率计可有可无，因为我们并不需要准确的测量绝对功率，只需要去淘宝买一个RF功率计模块（AD8310/AD8362）用六位半测量模块的输出电压再通过公式计算得到功率值就够了  
脚本还是Python2.7的，可以发给Ai让他帮你改到Python3并且去掉Qt相关的依赖
